## Decisions
- **`data-hub` sits on each template's root element, not on the site layout.** The layout is a server component shared by every route and cannot know which hub it is rendering without going dynamic; the templates already know.
- **The result panel is the left column on desktop via `order: -1`, but the questions stay first in the DOM.** A phone would otherwise open on an empty panel, and for tools 2 and 3 the inputs are what the visitor came for.
- **The header progress line is rendered only by tool 1.** It is the only tool with a step count; tools 2 and 3 are always "done" and a fake counter would be noise.
- **The aside "Vårt val" card renders the first `partners` entry inline rather than through `PartnerCta`.** `PartnerCta`'s list markup does not fit a 230 px card; the unconditional Annonslänk marking is identical either way, and `PartnerCta` still serves MDX and the tool pages.
- **"Mest lästa guider" lists the four newest guides** and says nothing about reads, per the contract — there are no read counts to show and inventing them is forbidden (§4.16).
- **The tool footnote falls back to an honest line.** Every constant in `src/lib/tax/constants.ts` still has `verifiedOn: null`, so "hämtade {datum}" would have been a blank; it now says the figures are not checked against the authorities yet and points at the source box.
- **The newsletter link carries `prefetch={false}`.** `/nyhetsbrev/` is S8's page; without it the router prefetched a 404 from every page and the e2e run (rightly) failed on it.
- `tests/screenshots.mjs`'s route list now ends in `/verktyg/bolagsform/` instead of `/verktyg/`, matching plan §5.4. No selector in `tests/tools.e2e.mjs` had to change.

## Known issues
- **"Mest lästa" is a heading without a metric.** It shows the newest four until real read counts exist; if they never do, the heading should become "Nya guider".
- The hub card grid on a room with many articles will eventually want pagination — at two published articles there is nothing to page.
- `home.trustRow` is now rendered only in the footer line; if a later phase wants the old trust row back it is one loop, the data is untouched.
- The six-room grid on mobile hides the descriptions (contract §2). Screen readers still get the title and the count, but the descriptions are simply not in the DOM there.
- `/nyhetsbrev/`, `/redovisningsbyra/`, `/om-oss/`, `/kontakt/`, `/annonspolicy/`, `/integritetspolicy/` and `/villkor/` are still 404 and reported by verify as warnings, unchanged from O2 and O3.
- The article body is `1fr 230px` with the prose capped at `68ch`, so on a 1440 px screen there is more white space to the right of the text than the canvas showed. It reads well; a later pass could widen the measure instead.
- Every one of O3's 22 tax constants still ships `verified: false`; D1 touched no number, only how the flag is drawn.
