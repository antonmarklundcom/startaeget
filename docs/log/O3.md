# O3 — Tools

## Built
- `src/lib/tax/constants.ts` — the single source of truth for every rate, fee and threshold (plan §4.16): 22 entries of `{ key, value, unit, label, validFrom, source, verifiedOn, verified, note }`, with `constant()`/`rate()`/`value()` accessors that throw on an unknown key or a unit mismatch.
- `src/lib/tax/income.ts` — grundavdrag and jobbskatteavdrag approximations, kommunal/statlig inkomstskatt, egenavgifter with the 25 % schablonavdrag, arbetsgivaravgifter, bolagsskatt and the 3:12 dividend split.
- **Tool 1 Bolagsformsväljaren** (`/verktyg/bolagsform/`): 8 questions, transparent additive scoring, hard exclusions (partners rule out enskild firma), a "därför" list built from the answers actually given, per-form next steps and partner slots, near-tie warning, shareable URL.
- **Tool 2 Startkostnadskalkylatorn** (`/verktyg/startkostnad/`): 16 line items filtered by bolagsform, every one editable, "vid start" vs "per månad" vs first-year totals, aktiekapital shown apart from money actually spent, print-the-checklist.
- **Tool 3 Vad blir kvar** (`/verktyg/vad-blir-kvar/`): enskild firma beside aktiebolag on the same surplus, rad-för-rad ledgers for both, own kommunalskatt, kr/hour, and the seven assumptions listed under the result.
- `src/components/tools/ToolSources.tsx` — the sources box every result ends with: each figure, its authority link and a `verifiera` flag where the value is still unchecked.
- `EmailResult` posts to `/api/tool-result` and degrades to a stored row with no `RESEND_API_KEY`; every result panel ends in `PartnerCta` + the byrå `LeadForm`.
- `src/components/home/HeroToolSlot.tsx` renders the hero question from `QUESTIONS[0]`, so the home page and the tool cannot drift; each answer links into the tool, which opens on question 2.
- `tests/tools.spec.ts` — 35 vitest cases (≥ 5 per tool); `tests/tools.e2e.mjs` — a scripted Playwright pass driving all three tools plus the hero handoff to completion.
- `content/tools.ts` flipped to `status: "live"`; SoftwareApplication JSON-LD via O2's shell; all three pages still prerender as static SSG (17.4 kB route JS, 123 kB first load).

## Decisions
- **One `/verktyg/[tool]/` route, not three directories.** Metadata, JSON-LD and the shell are written once; a single switch maps id → components. Three static dirs would have collided with `generateStaticParams` for no gain.
- **State travels by React context, not props.** The questions and the result sit in two different slots of O2's `ToolShell`, so each tool is a client provider wrapping the shell, with the slot fillers as consumers. The shell stays O2's and the pages stay static.
- **URL state is read on mount, not via `searchParams`.** Reading `searchParams` in the page would opt all three tools into dynamic rendering; reading `window.location.search` in an effect keeps them prerendered and still makes every result shareable and reload-safe.
- **Tool CSS lives in `src/components/tools/tools.css`**, imported once by `ToolFrame`, because `src/styles/**` is O2's to own (§4.9) and `phase.css` is the lane 2 escape hatch. Same tokens, so it reads as one product.
- **The "verifiera" explanation is rendered once per result panel**, not stamped on each constant. The first build repeated the same three-line caveat under eight figures and buried the tool; the per-figure flag plus one explanation at the foot of the box is as honest and legible.
- **Negative and nonsense inputs fall back to the default** rather than crediting the visitor, and a loss zeroes both columns in tool 3 instead of showing a negative "kvar till dig".
- **The AB case takes salary up to the brytpunkt and the rest as dividend.** It is the common advice, not always the optimum, so the result says so in the assumptions rather than presenting it as the answer.

## Known issues
- **Every one of the 22 tax constants ships `verified: false`.** The egress gateway answers 403 to CONNECT for `skatteverket.se`, `bolagsverket.se` and `verksamt.se` — confirmed 2026-09-11 via curl, WebFetch and the proxy's own status endpoint (same block O1 and O2 hit). Values were corroborated against independent secondary sources; each carries its authority URL and a `verifiera` flag in the UI. **A human must check them and flip the flags** — it is one edit per value in `constants.ts` and nothing else changes.
- **The 3:12 rules changed for 2026** — förenklingsregeln and huvudregeln are replaced by one rule with a grundbelopp of 4 inkomstbasbelopp (322 400 kr). The reform is recent and the secondary sources disagreed on the schablonbelopp; this is the constant most worth checking first.
- **Grundavdrag and jobbskatteavdrag are approximations**, not Skatteverket's tables. The shape is right, the krona is not; tool 3 says so in its assumptions and links out. Replacing them with the real tables is a contained change in `income.ts`.
- **The e2e pass is not wired into CI.** `.github/**` and `package.json` are O1's to own (§4.9), so `node tests/tools.e2e.mjs` has to be run by hand or added by a later phase. Suggested: a `test:tools` script plus a CI step.
- One run of the e2e reported a bare `404 (Not Found)` console error that did not reproduce across three later runs. The listener now records the method, URL and status of any 4xx, so a recurrence will name the request instead of being unactionable.
- Market-price lines in tool 2 (bank, bokföringsprogram, försäkring, webbhotell, e-handel) are ranges, not verified vendor prices — the same 403 blocks the vendors' own pages that O2 hit. S5 re-checks the bokföringsprogram figures; the tool's defaults should follow whatever it lands on.
- `/redovisningsbyra/`, `/om-oss/`, `/annonspolicy/` and the other S8 pages are still 404 and reported by verify as warnings, unchanged from O2.
